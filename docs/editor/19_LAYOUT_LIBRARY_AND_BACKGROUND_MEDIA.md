# Layout library and background media

October 22, 2026. Extends the existing version-2 project; does not replace the staff session, content owners, draft store or publisher.

## Authoring workflow

Select a section, row or column, then Insert. Layouts shows empty section, two/three/four columns, one-third/two-thirds, hero, feature cards and image/story presets with wireframe previews. Layout presets create real Section → Row → Column → Element blocks in a single undoable operation. Empty columns accept clicks and drops. Select a leaf to insert its next sibling. Exact section lines take precedence over the current selection. Insert here opens the library for the current target. Parent navigation and Section background make container selection explicit.

All existing approved inserts remain available. A row's Columns/Column proportions and its spacing/alignment can be changed for the selected device. New multi-column presets stack on phones and use at most two columns on tablets. Content, structure and ordering remain shared across devices; style overrides remain isolated.

Explicit section background overrides replace the homepage hero media/overlay visually at the chosen breakpoint. Resetting that device restores the canonical hero media; its settings values remain intact.

Background media is available in the inspector for sections and elements: colour, raster image path/HTTPS URL or staged upload, cover/contain, alignment, repeat, scroll/fixed, dark overlay, full-screen height, and direct video URL. Videos are muted, looping and inline; background image supplies the poster. Clear media records an explicit empty override, preserving the other device settings. Fixed backgrounds provide a CSS parallax effect where supported; this is not a scroll-animation timeline. Reduced-motion disables fixed scrolling and decorative background video. No video upload/transcoding service is added.

## Reuse, rather than a second backend

Instatic's MIT insertion resolver and module wireframe definitions are vendored under `editor/src/vendor/instatic/`, with attribution and a served license at `/licenses/instatic.txt`. The resolver accepts an injected container policy instead of importing Instatic's global registry. `LayoutLibrary.tsx` projects our flat placement graph into its node tree. Container insertion and the leaf sibling-after fallback therefore use the upstream algorithm. The wireframe definitions drive layout thumbnails. Existing source DOM uses its source-preserving placement adapter, retaining managed integration boundaries.

## Shared renderer contract

Section is an additional approved container type. Placement remains `{section, parent:'content', before?}` for typed containers. Existing source-container placement is unchanged. Sorting layers and the arrow controls retain the current parent; cross-parent moves use explicit canvas drop targets. Removing a block also clears sibling anchors that referenced it. Layout actions validate the full candidate before changing state; cycles, maximum nesting, maximum blocks and invalid targets remain rejected. Presets are ordinary blocks and can be duplicated/removed with their descendants using the existing operations.

Design keys are centrally validated in `content-core/design.cjs`; media URLs accept local absolute paths or HTTPS and reject CSS/HTML delimiters and executable schemes. No arbitrary CSS/HTML/scripts are admitted. Width/grid rules target the container once, avoiding compounded nested grids. Background image CSS and decorative video markup are generated by the same core used by canvas, immutable preview, API preflight and production build. Device media queries match the existing exclusive desktop/tablet/phone contract. Video changes use live reconciliation, not iframe navigation. Style edits retain live nodes and playback.

Staged background images use the existing IndexedDB asset collection. Only referenced assets are included by the existing atomic publish protocol. Save/autosave and immutable preview do not publish. Main SHA, source digests, canonical content versions and optional team-draft revisions retain their existing guards. The code deployment does not publish a staff design or add an active layout.
