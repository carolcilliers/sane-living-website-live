# Sane Living repository rules for people and agents

Read CLAUDE.md, DESIGN.md and docs/handbook/README.md before editing. This is `carolcilliers/sane-living-website-live`, not another Sane project. Honor the user's task scope: a dashboard task does not authorize a public website redesign.

- Work directly on main within the existing authorization. Do not create a branch or PR. Read the latest remote head before editing and again before publishing; preserve concurrent contributors. Use non-force, expected-head updates. An accepted commit is not a verified live deployment.
- Native dashboard: public/dash/app.js plus event-workspace.js. Layout primitives: workspace.css. Theme/material ownership: appearance.css and appearance.js. Dashboard styles never enter the Page Editor's website iframe.
- Content ownership, endpoints, schemas and page-specific rules are indexed in docs/handbook/README.md. Canonical files are public/content; shared drafts are dashboard-drafts and are not served by Vercel. This is a public Git repository: neither location is a secrets vault.
- Keep existing staff auth and server-only credentials. Never commit credentials or call staff write APIs without a task authorizing the content change. Use unique filenames for media; never overwrite originals. Image/video limits and signatures are in api/dash-save.js and the handbook.
- Saving is not publishing. Retain both published and shared-draft SHA checks, local recovery, unknown authored fields, failed-load protection and persistent error states. Do not silently resolve a conflict by replacing the expected SHA or loading blank content.
- Airtable owns calendar records and public calendar visibility. Event stories own rich descriptions, hosts, galleries, recordings and planning/archives. An unlinked story is not a booked/published calendar event. Do not invent missing flyer dates, host names or wedding permission. Do not automatically recreate a calendar entry after an ambiguous network failure: reload and inspect existing records first.
- Event-story publication filters approved records; unapproved working stories stay in the shared draft. Never publish the whole planning collection as a public feed. Public calendar debug modes require staff auth. Preserve the Publish filter.
- One file per public route; no `.html` / directory-index twins. Follow content/page-templates.json ownership and the editor migration rules before changing trusted page snapshots or active published layouts. Do not commit generated public/dash/editor, test layouts or test release descriptors.
- Run meaningful fixture tests for the changed user flows, typecheck and build. Inspect rendered light/dark phone and desktop views; test real controls, not just selectors or build success. Test against isolated fixtures, never real Airtable/GitHub content. Verify the Vercel commit status and exact live assets before claiming deployment complete.

Start with the matching dashboard rulebook; use public-pages/INDEX.md for a marketing-page source map. Page Editor's detailed implementation contracts remain under docs/editor. Record limitations honestly; do not claim full Webstudio parity or a live Airtable verification without evidence.
